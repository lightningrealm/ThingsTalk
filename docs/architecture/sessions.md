# 架构与会话生命周期

采用 Clean Architecture：domain 定义设备、面板、BLE、MQTT、事件等契约；data 实现解析、存储和平台适配；presentation 通过 ViewModel、协程和 StateFlow/Flow 管理界面。Compose 不直接持有底层设备连接。

## 连接

设备会话属于应用作用域，前台页面切换不会主动断开。用户手动停止、设备释放和工作区销毁会清理资源。Android BLE 与设备 MQTT 沿用后台停止策略；iOS 在已有 bluetooth-central 配置下保留 BLE 会话/订阅。App 被强制结束后不保证恢复，也不承诺任意后台状态永久运行。

iOS 恢复已保存设备需要等待蓝牙管理器初始化，再使用系统 peripheral UUID 查找。GATT 操作须正确关联服务与特征实例；同 UUID 多实例时不能以字符串相等替代唯一定位。Notify 订阅状态与系统推送无关。

MQTT 使用 MQTT 5 + WS/WSS、干净会话；订阅消息无 replay，应在连接/订阅操作之前建立收集。工作台与设备使用独立会话，固定 Client ID 并发可能互相踢下线。没有自动跨通道回退或命令补发。

## 事件与状态

BLE 在脱敏后的 trace 入口采集，MQTT 在仓库装饰器采集，设置保存结果通过会话装饰器记录，不依赖消息页存在。展示状态按需要订阅，高频流量不驱动无关页面。

Broker 确认不代表设备执行成功，GATT 写响应不代表固件保存完成，配置保存成功也不代表 Wi-Fi/MQTT 已连通。业务确认需遵循协议回执。

## 持久化与编辑

设备仓库串行化修改，成功保存后发布状态；从配置创建时设备与面板一次写入。草稿与已保存定义分开，恢复冲突先由用户处理。文件返回早于草稿加载时等待加载，不静默丢弃导入。

后台常驻服务、系统通知、规则引擎和离线事件补收不属于当前实现。跨平台编译和模拟器测试不能替代外设、Broker、锁屏、权限撤销及进程终止场景的真机验收。
