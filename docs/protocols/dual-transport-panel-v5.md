# BLE + MQTT 双连接设备与面板 v5

2026-10-31。一个逻辑设备可以同时拥有 BLE 外设关联与 MQTT 连接。面板组件仍然引用 capabilityId，由该能力的绑定指定控制通道和状态来源。

## 使用方式

Android/iOS 创建自定义设备时选择 **BLE + MQTT**。已有 BLE 或 MQTT 设备也可在设备连接区域选择“升级为 BLE + MQTT 双连接设备”。升级会断开会话，保留设备 ID、组件、协议、BLE 关联和 MQTT 地址；原有绑定沿用原通道。未应用草稿不会覆盖已保存配置，恢复旧草稿时转换为双连接格式。

手机端设备展示页顶部常驻 BLE / MQTT 左右 Tab，单通道设备也可见；未启用的通道显示升级入口（升级会断开当前连接，保留组件与绑定），已有通道展示对应连接卡。下方仍是共用控制面板，标签同时显示各自连接状态；两条连接分别连接/断开，切换 Tab 不断开连接，重新关联 BLE 外设不会断开 MQTT。开发者设置中的“协议与面板编辑”使用 BLE / MQTT Tab 分别填写特征读写通知和 topic 发布订阅，控制通道和状态来源保持显示在 Tab 上方。标签只决定编辑哪一侧，不更改路由，不拆分组件或 JSON。输入内容在切换时保留。保存仍在顶栏。

例：电源开关的控制走 BLE write，状态来自 MQTT subscribe。两个连接都建立时，点击开关只写 BLE；显示值只接受 MQTT 状态，即使 BLE 也配置了 read/notify，也不会自动读取或订阅它们。也可以把状态来源选为 BLE，或为不同组件选择不同通道。

当前 Web 入口仍只创建 MQTT v4 设备；双连接设备创建、升级及 v5 文件导入面向 Android/iOS。Web 没有 BLE 支持。独立 MQTT 工作台保持原有行为。

## 配置契约

- BLE：旧 v1/v2/v3 配置继续支持。MQTT：v4 + `transport: "MQTT"`。
- 双连接：`schemaVersion: 5` + `transport: "DUAL"`。
- binding 可同时包含 `read` / `write` / `notify` 和 `publish` / `subscribe`，两类操作各自沿用既有格式。
- 有 write 或 publish 时，必须显式指定 `controlTransport: "BLE" | "MQTT"`，且该通道配置了对应控制操作。
- 有 read/notify 或 subscribe 时，必须显式指定 `stateTransport: "BLE" | "MQTT"`，且该通道配置了对应状态操作。
- 没有控制/状态操作时，不填写相应选择。选择不能为 DUAL。两条通道配置都需校验通过，未选中的配置也不能保留无效 UUID/topic/格式引用。
- 同一能力只使用一个控制通道和一个状态来源。BLE 状态来源可同时启用读取与通知；MQTT 状态来源只订阅，不提供通用“读取”操作。
- BLE 与 MQTT 可引用不同 payloadFormat，以适配二进制 BLE 和 JSON MQTT。二者最终均解析成同一能力的数值/布尔值。
- BUTTON/ACTION 两条通道均只能控制，不能绑定状态读取/通知/订阅。固定报文规则保持不变。
- 双连接设备可导入旧单通道文件，自动提升为 v5 并沿用原通道；这是整份面板替换，不是合并两份配置。编辑器明确提示替换行为；导入 MQTT-only 后不会自动生成 BLE UUID，双连接编辑器仍可在 BLE Tab 补充映射。单通道设备不能直接导入 DUAL 文件，先升级设备。
- 面板文件不含 BLE 平台标识、MQTT 地址、账号或密码。使用者分别关联本机外设、选用本机 MQTT 连接配置。

可导入的最小示例：[dual-power.thingstalk.json](../examples/dual-power.thingstalk.json)。示例 UUID/topic 是演示协议，需替换为真实固件值。BLE 电源字节为 `00` / `01`；MQTT 使用 `{"power":true}` / `{"power":false}`。

## 运行时与生命周期

Domain 定义双连接绑定、校验和旧配置提升；Data 的 `DualPanelOperations` 根据显式路由调用既有 BLE/MQTT 适配器；Presentation 的设备工作区管理两个独立会话，面板 ViewModel 维护状态和局部组件投影。

连接注册表通过 StateFlow 驱动状态观察。只有所选状态通道变化才替换订阅；另一通道连接/断开不重建健康订阅。选择 BLE 时先建立通知再读取初值，读取期间有新通知到达则丢弃较旧读值。失败显示在组件中，可手动重试；用户重新连接后重新建立状态订阅。

失去控制通道会取消该通道的执行中/排队操作，并禁用相应控件；失去状态通道会清除相应显示值。两者分别处理，另一条通道仍可运行。旧连接的迟到结果不会更新新连接状态。已发送的命令是否被硬件执行无法通过取消撤销，需要设备状态或业务回执确认。

不自动跨通道切换，不自动重连，不自动补发控制命令。MQTT QoS 确认和 BLE GATT 写入确认都不等于硬件业务执行成功。重连只恢复选定状态观察，不恢复命令队列。销毁设备工作区会断开会话。后续 iOS 生命周期修复已改为后台保留 BLE 会话及订阅，MQTT 仍断开；其他平台仍按原后台策略断开，见 [iOS BLE 后台会话](../architecture/sessions.md)。没有系统推送或进程终止后的自动恢复。
